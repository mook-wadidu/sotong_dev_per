# 소통 파일럿 케이스 로그 — 설정·기입 가이드

파일럿의 **진짜 산출물은 이 로그**다. 소통 DB는 WADIDU 파일럿 계정 하나로만 돌아가고
실제 매장·디자이너는 여기에만 남으므로, **미완결·상담단계 케이스는 이 시트가 유일한 기록이다(복구 불가)**.
→ **케이스 종료 직후 현장에서 즉시 기입**한다. 나중에 몰아서 쓰면 절반은 날아간다.

## 셋업 (구글시트)
1. 구글시트 새 문서 → **파일 → 가져오기 → 업로드**로 `case-log.csv` 올림(구분자 쉼표).
2. 예시행(C001·C002) 2줄 삭제.
3. 아래 **드롭다운(데이터 확인)** 을 걸어 표기를 통일한다 — 손입력하면 "홍대A"/"홍대 A점"으로 갈려 집계가 깨진다.
   - 열 선택 → **데이터 → 데이터 확인 → 드롭다운(항목 목록)**.

## 드롭다운 값 (WADIDU가 자기 파일럿에 맞게 채움)
| 열 | 값 | 규칙 |
|---|---|---|
| 매장 | 예: `홍대A`, `홍대B`, `청담A` … | 파일럿에 실제 쓰는 매장만. 새 매장 생기면 목록에 추가 |
| 디자이너ID | 예: `홍대A-D1`, `홍대A-D2`, `홍대B-D1` … | **반드시 매장 접두어**. 매장별로 D1부터 다시 쓰면 서로 다른 사람이 한 명으로 합쳐져 "같은 디자이너가 2건째부터 자발적인가"가 깨진다 |
| 시술종류 | `커트`, `펌`, `염색`, `클리닉`, `스타일링`, `기타` | |
| 국적/언어 | `일본`, `영어권`, `중국`, `한국`, `기타` | |
| 막힌항목 | `없음`, `언어`, `항목`, `사진`, `기타` | 손님이 사전작성 중 막힌 지점 |

## 열 정의
| 열 | 뜻 | 비고 |
|---|---|---|
| 케이스ID | WADIDU 일련번호 `C001`… | 시트 내부 식별 |
| **상담ID** | 소통 상담 id **앞 6자리** | **시트↔DB 조인키.** 완결레코드율을 DB와 교차검증할 때 이게 없으면 케이스를 손으로 대조해야 함 |
| 날짜 | `YYYY-MM-DD` | |
| 해당디자이너N번째 | 그 디자이너의 파일럿 N번째 케이스 | 선택 — 비우면 날짜순으로 계산됨 |
| 사전작성완료 | 손님이 **매장 도착 전** 앱 작성을 마쳤나 `Y/N` | N이면 현장 작성한 것 → 사전작성 가설 반증 |
| 소요(분) | 손님 작성 소요 | 링크 다시 찾기 등 마찰 있으면 오염되니 실제 작성 시간만 |
| 만족도 | 리포트 수령 후 `1~5` | |
| 요약봤나 | 디자이너가 한국어 요약을 실제로 봤나 `Y/N` | |
| 모발상태자발입력 | 디자이너가 모발상태를 **스스로** 입력했나 `Y/N` | N=WADIDU 대행 |
| **AI초안수정량** | 디자이너 확인 시 초안을 얼마나 고쳤나 `0~3` | 0=그대로 발송 … 3=대폭 수정. "AI 초안이 쓸 만한가" 지표 |
| **자발성** | 디자이너가 이 케이스에서 어디까지 스스로 했나 `0~3` | 0=전부 WADIDU 대행 … 1=요약만 읽음 … 2=모발상태 입력까지 … 3=리포트 OK까지 스스로. **점진 이양=확장성 열쇠** |
| 완결레코드 | 상담+결과+사진까지 다 채워졌나 `Y/N` | 반쪽 데이터 방지 |
| **리포트재열람** | 손님이 리포트를 **나중에 실제로 다시 열었나** `Y/N` | 개인 링크(내 링크)를 저장해뒀다가 재방문했는지. **알림채널(왓츠앱 등) 필요성 판단 근거** — 재열람이 낮으면 손님이 리포트를 안 챙기는 것 → 푸시/링크 재전송이 필요하다는 신호 |
| 배운것 | 이 케이스에서 관찰한 것(자유) | 정량으로 안 잡히는 마찰·놀람 |

## 이 로그가 답해야 할 학습질문
1. 손님이 **사전작성을 실제로 하는가**(사전작성완료 Y 비율, 막힌항목 분포)
2. **AI 초안이 수정 최소로 발송 가능한가**(AI초안수정량 분포)
3. **디자이너가 어디까지 자발적인가 / 2건째부터 올라가는가**(디자이너ID별 자발성 추이)
4. **완결률이 유의미한가**(완결레코드 비율)
