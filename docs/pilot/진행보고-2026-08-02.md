소통을 **"손님 사전작성 → QR로 디자이너에게 제시 → 디자이너 검수 → AI 리포트"** 흐름으로 전환하고,

## 1. 방향 전환 (왜)
기존 "디자이너가 손님에게 권유" 구조는 바쁜 현장에서 유지되기 어려웠다. 이를 뒤집어:
- **손님**이 매장 도착 **전** 자기 언어로 시술지를 탭 입력(타이핑 최소).
- 매장에서 **QR을 디자이너에게 제시** → 디자이너/WADIDU 태블릿이 스캔해 한국어 요약 열람.
- 디자이너는 **읽기 + 칩 + 모발상태 등급만**(타이핑 0). 나머지는 손님 입력 + AI가 처리.
- 완료 시 **AI 리포트 초안** → 확인 → 손님 수령.

**파일럿은 컨시어지**(WADIDU가 외국인 손님을 하나하나 섭외·동행, 10~20명). 목적은 매출이 아니라
**학습** — "손님이 사전작성을 하는가 / AI 초안이 수정 최소로 발송 가능한가 / 디자이너가 어디까지
자발적인가 / 완결률이 유의미한가". 시스템 완성도가 아니라 사람 문제를 검증한다.

### B. Supabase 서울 이전 (완료·검증)
- 새 서울 프로젝트(`hayiibbdxzpztomwojcc`, **ap-northeast-2**) 생성 → 마이그 **0001~0026** 전체 적용.
- Vercel 프로덕션 env를 서울 값으로 교체(URL·anon·service_role) + admin 토큰·entry 시크릿 재설정 + 재배포.
- **prod→Seoul 연결 확정** — admin 진입(rate_limits 쓰기) + E2E(상담 생성) 모두 서울에 정상 기록.
- 구 시드니 DB는 삭제됨(실데이터 0, 테스트뿐이라 손실 없음).
- ⚠️ **발견·수정한 버그**: `locales` 참조 테이블 seed가 마이그 밖(수동)에 있어 스키마만 이전한 서울엔 없었고, 상담 생성이 FK 위반으로 500 났다 → **마이그 0026으로 seed를 박아** 재발 방지.
- ⚠️ **주의**: Supabase **Auth 계정**(admin/owner/designer 이메일·비번 로그인)은 이전되지 않았다(auth.users는 마이그 밖). 서울엔 계정 0. 현재 admin은 **공유키**로 우회 진입 중. 이메일/비번 계정이 필요해지면 서울 Supabase Auth에 새로 생성.

### C. 파일럿 코드 (브랜치 `feat/pilot-flow-prep`, 커밋됨·미푸시)
- **A0** — 케이스 로그 CSV + 가이드(`docs/pilot/`). 매 건 계측(사전작성완료·소요·AI초안 수정량·디자이너 자발성 0~3·완결·**리포트 재열람** 등). 파일럿의 진짜 산출물.
- **A2** — 리포트에서 **약제(성분) 완전 제거** + **색감(결과)·실매장명** 추가 + **디자이너 실명 미표시**(→"담당 디자이너"). 실매장명은 디자이너가 리포트 시 수동 입력(파일럿 DB 살롱은 단일 계정이라).
- **A3** — 얼굴형·두상·색감을 **손님이 자가입력** → 디자이너가 검수·수정.
- **A4** — 파일럿용 최소 핸드오프: 제출 후 **제시-QR 화면**(직원 스캔용 단수명 토큰) + `/h/<token>`이 해당 상담의 디자이너 요약으로 리다이렉트.
- **A5** — 인테이크에 **이름(선택)·국적** 수집.
- **A6** — **재진입 보강**: 개인 링크가 완료 전엔 QR, 완료 후엔 **리포트 보기 CTA**로 전환(adaptive) + **"내 링크" 복사 노출**("저장해두세요, 나중에 리포트를 여기서 확인"). 기기 무관 재진입 보장.
- **손님 화면 전체에서 지점명 제거** — 파일럿은 살롱을 정해놓고 하는 게 아니라(손님이 먼저 작성→디자이너에게 제시), 손님 화면에 소속 지점을 단정하지 않는다.

### D. 배포 · 검증
- 프로덕션 서울 배포, 부팅 정상.
- **E2E(프로드+서울) 전 과정 통과**:
  인테이크(이름·국적·얼굴형/두상/색감 포함) → 제출(**상담 서울에 생성**) → present(**핸드오프 QR + 내 링크 복사** 확인) → 핸드오프 QR 스캔 `/h` → **디자이너 한국어 요약 도달** → **재진입(쿠키 없는 새 브라우저에서 개인 링크 열기 → 자기 상담 로드)**.
- **WADIDU 파일럿 살롱** 시드(순수 DB 컨테이너, slug `wadidu`).

## 3. 파일럿 실행 프로세스 (확정)

| # | 누가 | 뭘 |
|---|---|---|
| 1 | WADIDU | 섭외 — 외국인 방문객·유학생(홍대 현장 피켓 + 국제처 경로 병행) |
| 2 | WADIDU→손님 | 현장 QR 제시 + 링크 전달 병행 (살롱 컨테이너가 여기서만 쓰임) |
| 3 | 손님 | 자기 언어 탭 입력(이름·국적+시술·사진·이력·고민·알레르기·얼굴형/두상/색감·동의) → 제출 → 제시-QR |
| 4 | 손님→ | 제시-QR을 디자이너/WADIDU 태블릿에 보여줌 |
| 5·6·8 | **디자이너(초기 WADIDU 대행)** | 스캔→요약 열람 / 요약읽기+모발상태 입력+얼굴형·색감·두상 검수 / 기록→AI 초안→손님 수령 |
| 8.5 | WADIDU | 리포트 수령 직후 손님 만족도·막힌항목 확인 |
| 9 | WADIDU | 케이스 로그(구글시트) 기입 |

- 초기엔 5·6·8을 WADIDU가 태블릿으로 대행/밀착보조하고, **"디자이너 자발성 0~3"을 매 건 관찰**(점진 이양=확장성 열쇠).
- 파일럿엔 리포트 승인 게이트 없음(WADIDU 입력이 검수 대체) — 정식 단계에서 초안→확정→승인 추가.
- 알림 채널(왓츠앱 등)은 **안 함** — 전화번호 수집+Meta 경유가 "국외이전 최소" 포지션을 깨서. 손님이 원하면 손으로 링크 전달. 필요성은 케이스 로그의 "리포트 재열람" 데이터로 판단.
